## 1. 총평 (핵심 진단)

**디자인 시스템(DESIGN.md)은 상급인데, 화면이 시스템을 절반만 입고 있다.**
토큰(웜 뉴트럴, 헤어라인, radius 0)은 전면 준수 중 — R6/R7이 지켜주고 있다.
그러나 시스템의 **시그니처**(에디토리얼 비대칭 레이아웃, 대문자 그로테스크 라벨의
자간 위계, "필 CTA 하나 + 나머지는 텍스트 링크" 규칙, 모바일 햄버거 드로어)는
홈 히어로 이후 어디에도 구현되어 있지 않다. 그 결과 퍼널은 "고급 셀렉트샵 입구 →
관공서 민원 양식"으로 톤이 급락한다. 메이커가 느낀 "일반적인 버튼 투성이"의 실체다.

카드의 구조(No./세리프 제목/헤어라인 가격행), 컬러·여백 토큰 준수, 콘텐츠 카피의
정직성(과장 없음), 체크아웃의 폼+요약 2열 골격.

> 참고: DESIGN.md가 "구현 참고용 완성 페이지"로 가리키는 `designs/09-atelier-sans.html`은

## 2. 디자인 원칙 (전 워크패키지 공통 — DESIGN.md 준수 확인란)

1. **화면당 네이비 필 CTA는 1개.** 나머지 행동은 텍스트 링크(`뒤로`, `건너뛰기 →`) —
   hover 시 화살표 5px 이동 + 네이비. 박스형 secondary 버튼은 전면 폐지.
2. **색·모서리·그림자 신설 금지.** 기존 토큰만. 악센트는 CTA·활성·점·번호·포커스에만(<5%).
3. **폼은 밑줄 스타일**(DESIGN.md §Components #4): 1px `--line` 하단선, `:focus-within`
   네이비. 라디오/체크박스는 네이티브 숨기고 칩·토글로 렌더(키보드 접근성 유지).
4. **세리프는 책 제목만.** 스텝 라벨·버튼·가격은 그로테스크, 라벨은 대문자+자간 0.14~0.20em.
5. **터치 타깃 ≥44px**, 한글 본문 줄간 1.75/자간 0/`keep-all` 유지.
6. **E2E 계약 보존**: 모든 `data-testid`·role·문구(스펙이 매치하는 텍스트)는 그대로 둔다.
   구조 변경 시 해당 spec을 먼저 읽고 나서 마크업을 옮긴다.

## 3. 워크패키지 (우선순위순, 세션당 1개)

### WP1 — CTA·버튼 체계 재정립 (퍼널 전 구간의 '버튼 투성이' 해소) ★최우선

  `CtaPrimary`(필: 기존 `.cta` 스펙 보정 — 자간 0.18em, padding 1.05em/2.2em, hover
  투명+테두리 유지), `TextAction`(텍스트 링크: 그로테스크 대문자 0.72rem + ` →` 화살표
  hover 5px 이동, button/Link 겸용), 뒤로가기 전용 `BackAction`(`← 뒤로`).
  order/cart/checkout/mypage의 모든 `.back`·보조 버튼을 TextAction으로 교체.
  `styles.back` 삭제. 모바일에서 CtaPrimary는 full-width 유지하되 스텝 내비는
  "좌 텍스트(뒤로) / 우 필(다음)" 한 줄 정렬.
- **파일**: Button.tsx, globals.css(.cta 보정), order.module.css, 각 Step, CartView,
  CheckoutView, MypageLookup, FinishingClient.
- **검증**: `pnpm check` + `pnpm test:e2e -- order-start checkout` + 1440/390 스크린샷.
  기존 testid 전부 보존(버튼 태그는 유지, 클래스만 교체).
- **리스크**: 낮음. 시각 전용, 행동 불변 → 신규 feature row 불요(F002 폴리시 선례).

### WP2 — 폼 컨트롤 키트 (네이티브 컨트롤 전면 교체)
- **내용**: `src/app/_components/form/` 신설 —
  `ChoiceChip`(라디오 대체: 칩 안에 라벨+보조가격, 선택 시 네이비 테두리+체크 인디케이터
  `●`, 실제 input은 시각적으로만 숨김), `ToggleRow`(QR 옵션: 체크박스 → 헤어라인 행 +
  우측 상태 라벨), `UnderlineField`(텍스트/이메일/date 공통 밑줄 스타일 + 라벨 대문자화,
  date는 한국어 힌트 라벨 "예: 2025-11-20" 추가), `FileDrop`(파일 인풋 →
  4:5 `--panel` 드롭 매트 + "사진 올리기 ↑" 텍스트 + 업로드 후 **미리보기 썸네일**로 교체,
  기존 업로드 액션 재사용).
  성별 라디오(남아/여아)와 커버 선택을 모두 ChoiceChip으로 통일.
- **파일**: _components/form/* (신규), InfoStep, PhotoStep, CoverStep, order.module.css,
  ContactForm, MypageLookup(입력 밑줄화 공유).
- **검증**: `pnpm check` + order-start·mypage 관련 E2E + 스크린샷. input을 DOM에서
  제거하지 않으므로(視覺만 숨김) 기존 `click [data-testid=...]` 흐름 그대로 동작.
- **리스크**: 중간 — E2E가 라디오를 직접 click하므로 label-wrapping 구조 유지 필수.
  FileDrop 미리보기는 로컬 objectURL만 사용(사진은 PII — 로그·트레이스 금지 유지).

### WP3 — 주문 위저드 리컴포지션 (퍼널의 '상품 실종' 해소)
- **내용**:
  ① 퍼널 전용 **컴팩트 헤더**: `--section` 히어로 대신 상단 여백 `--space-lg`,
  eyebrow(템플릿 라벨) + h1은 **책 제목을 세리프로**("『탄생』 주문 만들기" 형태 —
  세리프는 책 제목 부분에만) + 한 줄 blurb. 모바일에서 폼이 첫 화면 안에 들어오게.
  ② **스텝 인디케이터**: `01 아이 · 02 사진 · 03 커버 · 04 확인` 대문자 라벨 행,
  현재 스텝 네이비+밑줄(활성 내비 패턴 재사용). `aria-current="step"`.
  ③ **데스크톱 7/5 분할**: 좌 폼(640px) / 우 sticky 레일 — 4:5 타이포그래픽 커버 매트
  (WP5의 컴포넌트 재사용: 패널 바탕 + 세리프 제목 + `No.`) 아래 주문 요약(선택이
  진행될수록 행이 채워짐: 이름 → 사진 → 커버 → 가격). 모바일은 레일 생략, 대신
  ④ **모바일 sticky 하단 바**: 현재 스텝 CTA + 현재 금액(커버 스텝부터) 고정.
  ⑤ 리뷰 스텝 요약 카드는 우레일과 동일 컴포넌트 재사용.
- **파일**: OrderWizard.tsx, order.module.css, steps/*, (신규) order/StepIndicator.tsx,
  order/SummaryRail.tsx.
- **검증**: `pnpm check` + `pnpm test:e2e -- order` 전체 + `pnpm eval`(퍼널 무회귀 필수)
  + 1440/390 스크린샷.
- **리스크**: 중상 — 위저드는 E2E 밀도가 가장 높음. 마크업 이동 전 spec 정독.
  **행동 추가(스텝 표시·요약 레일)가 있으므로 신규 feature row로 append** 권장
  (예: "F049 주문 위저드 UI 리컴포지션", E2E는 기존 order spec 확장으로 충족).

### WP4 — 내비 개편: BAG 진입점 + 모바일 드로어
- **내용**: ① 우측에 `BAG` 텍스트 링크 추가(→ /cart). 담긴 수는 localStorage 카트에서
  클라 사이드로 읽어 `BAG 1` 형태(0이면 그냥 BAG, 배지·원형 카운터 금지 — 조용함 유지).
  ② 모바일(<720px): 링크들을 햄버거 버튼(`메뉴`)으로 접고 DESIGN.md 스펙의
  **다크 패널 드로어**(`--ink-strong` 바탕 + `--on-dark` 링크, 전체 높이, 우측 슬라이드)
  로. 드로어 안에 카테고리 3개 + 주문 조회 + BAG + 콘텐츠 링크 5종(푸터와 동일).
  ③ 내비 라벨 타이포를 스펙으로(0.70~0.82rem, tracking 0.16em, 대문자 — 한글 메뉴명은
  대문자 무의미하므로 자간만 0.06~0.08em로 절제 적용; 영문 eyebrow만 풀 스펙).
- **파일**: Nav.tsx(+클라 컴포넌트 분리), globals.css.
- **검증**: `pnpm check` + home/order-confirm E2E(내비 링크 계약: "주문 조회" 텍스트
  보존!) + 390 스크린샷. **행동 추가 → 신규 feature row append 권장**
  (예: "F050 내비 카트 진입점+모바일 드로어", 자체 E2E: 모바일 뷰포트에서 드로어 열고
  /cart 도달).
- **리스크**: 중간 — a11y(드로어 포커스 트랩, `aria-expanded`), reduced-motion 가드.

### WP5 — 빈 매트 → 타이포그래픽 커버 (사진 도착 전 기본값)
- **내용**: (신규) `TypographicCover` — 4:5 `--panel` 매트 위에 중앙 정렬로
  세리프 책 제목(『탄생』) + 상단 `No. 01` + 하단 microLabel(카테고리 영문).
  실사진(heroImageUrl)이 오면 자동으로 이미지로 대체되는 기존 분기 유지.
  TemplateCard·갤러리 타일·(WP3) 위저드 레일·(WP6) 카트 썸네일이 공유.
  갤러리 "준비 중" 문구는 매트 밖 캡션으로 유지(정직성 보존).
  모바일 카테고리 그리드는 매트 높이를 화면 폭 기준 과대하지 않게(1열에서 4:5 → 4:3
  비율로 축소해 '빈 화면 5스크린' 완화 — 이미지 도착 후 4:5 복귀 여부는 그때 재평가).
- **파일**: _components/TypographicCover.tsx(신규), TemplateCard, GalleryTile,
  TemplateCard.module.css 등.
- **검증**: `pnpm check` + 카테고리 E2E(카드 계약: 라벨·가격 텍스트 불변) + 스크린샷.
  시각 전용 → feature row 불요.
- **리스크**: 낮음. 세리프 사용처가 '책 제목'이므로 규칙 합치.

### WP6 — 카트·체크아웃 폴리시 + 라인 삭제

  ④ 모바일: 총액+결제하기 sticky 하단 바(WP3 패턴 재사용).
- **파일**: CartView, CheckoutView, order.module.css, checkout.module.css,
  src/lib/cart.ts(라인 삭제 함수 — 이미 없으면 `removeLine` 추가).
- **검증**: `pnpm check` + checkout·cart E2E + `pnpm eval` + 스크린샷.
  **라인 삭제는 행동 추가 → 신규 feature row append** (예: "F051 카트 라인 삭제",
  자체 E2E: 담기 → 삭제 → 빈 카트). 결제 금액 로직은 불변(서버 스냅샷 가격 그대로).
- **리스크**: 중간 — 카트 구조는 Toss 리다이렉트 왕복을 견뎌야 하므로 저장 포맷 불변.

### WP7 — 모바일 글로벌 패스
- **내용**: ① 터치 타깃 일괄 ≥44px(내비·푸터 링크 padding, 칩 높이). ② 퍼널 외
  페이지 히어로도 모바일 수직 패딩 축소(`--section` → `clamp(48px,8vw,160px)` 재조정
  — 토큰 값 수정은 DESIGN.md와 globals.css 동시 갱신). ③ iOS safe-area(`env()`)
  sticky 바에 반영. ④ 16px 미만 input 폰트 금지(iOS 줌 방지 — 현재 1rem이라 OK, 회귀
  가드만). ⑤ 콘텐츠 페이지 좌우 여백/행간 모바일 최적화.
- **검증**: `pnpm check` + perf.spec(p95<2s 예산 유지) + 390 전 페이지 스크린샷.
- **리스크**: 낮음. 시각 전용 → feature row 불요. 토큰 수정은 DESIGN.md도 함께
  갱신해 SoR 드리프트 방지.

### WP8 — 콘텐츠 페이지 에디토리얼 정리 (마감)
- **내용**: ① 브랜드 스토리·맞춤 제작·후기를 4/8 비대칭 분할(좌 sticky 라벨 / 우 본문)
  로 재배치 — 우측 죽은 공간 해소. ② FAQ를 `<details>` 기반 아코디언 어포던스로
  (질문 우측 `+` 그로테스크 인디케이터, 열림 시 `–`). ③ 후기 페이지의 80% 스탯 카드를
  헤어라인 인덱스 행으로(박스 제거). ④ 문의 폼 밑줄화(WP2 재사용).
- **검증**: `pnpm check` + faq/content E2E(문구 계약 보존) + 스크린샷.
  시각 전용 → feature row 불요(FAQ 아코디언은 기존 FaqItem 동작 확인 후 판단).
- **리스크**: 낮음.

## 5. 실행 규칙 (하네스 합치)

- **순서**: WP1 → WP2 → WP3 → WP4 → WP5 → WP6 → WP7 → WP8. 각 WP는 한 세션,
  `pnpm check` green + 해당 E2E + (퍼널 터치 시) `pnpm eval` 무회귀 후 종료.
- **feature_list**: WP3(위저드 리컴포지션)·WP4(BAG+드로어)·WP6(라인 삭제)은 행동이
  추가되므로 **신규 row append**(R9 허용 경로) + 자체/확장 E2E로 DoD 충족. WP1·WP2·
  WP5·WP7·WP8은 F002 비주얼 폴리시 선례를 따라 row 없이 진행(계약 불변 확인 필수).
- **금지선**: 새 색·그림자·radius·두 번째 악센트 금지(R6/R7이 잡음), 기존
  testid/문구 계약 훼손 금지, 결제·가격 로직 불변, 사진 PII 로그 금지.
- **자산 의존**: 실사진(카테고리 8종, 갤러리, 키트)은 백스테이지 파이프라인 몫.
  WP5의 타이포 커버가 도착 전 기본값이므로 **웹 작업은 사진을 기다리지 않는다**.
  사진 브리프는 `docs/superpowers/specs/2026-07-04-hero-category-photo-brief-design.md` 부록.
