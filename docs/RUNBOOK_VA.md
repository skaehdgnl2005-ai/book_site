# 가상계좌(무통장입금) 운영 런북 — RUNBOOK_VA

> F081. 대상: 운영자(관리자). 전제: 가상계좌 주문의 상태 기계는 F070 —
> 발급(`WAITING_FOR_DEPOSIT`) → 입금 웹훅 → `PAID`, 미입금 만료 → `CANCELLED`(터미널).
> **`CANCELLED`에는 `REFUNDED` 엣지가 없다** — 이 문서의 모든 주의가 여기서 나온다.

## 1. 정상 흐름 (자동 — 손댈 일 없음)
- 구매자가 가상계좌를 선택하면 주문은 `WAITING_FOR_DEPOSIT`(발급 계좌·기한 안내).
- 입금이 확인되면 Toss 입금통보 웹훅이 `PAID`로 정산(확인 메일 정확히 1회).
- 기한까지 미입금이면 Toss가 `EXPIRED` 웹훅을 보내고 주문은 자동 `CANCELLED`(F070).

## 2. 수동 미입금 종료 (만료 웹훅 미도착/지연 시)
관리자 주문 상세(`/admin/orders/<orderId>`)의 **미입금 종료** 패널을 사용한다.

1. 상세에서 **입금 기한 · "기한 만료"** 표시를 확인한다. (기한 전에는 서버가 종료를 거부한다)
2. 로컬(운영자 머신, `MYPAGE_ACCESS_SECRET` 필요)에서 승인 토큰 발급:
   `pnpm approve order.close_unpaid_va <orderId>`
3. 발급된 토큰(이 주문·10분 한정)을 패널에 붙여넣고 **미입금 종료(주문 취소)** 실행.
4. 감사 로그(`/admin/audit`)에 `미입금 종료 · WAITING_FOR_DEPOSIT → CANCELLED` 행을 확인한다.

**기한 전 종료가 막혀 있는 이유(우회 금지):** 은행 입금은 비동기로 도착한다. 기한 전 취소는
실입금과 경합해 돈이 Toss에 들어왔는데 주문은 터미널 `CANCELLED`이 되는 사고를 만든다 —
그 상태의 실입금은 앱 안에서 환불할 방법이 없다(§3). 서버 게이트를 우회하려 하지 말 것.

## 3. 뒤늦은 입금 (종료 후 입금이 도착한 경우)
종료(`CANCELLED`) 후 도착한 입금 웹훅은 **절대 재정산되지 않고**(F070: `CANCELLED`은 markPaid
제외) 다음으로 감지된다:

- `/admin/audit`에 **"뒤늦은 입금 감지"**(행위자 **시스템**) 행 append.
- 서버 로그: `late deposit after cancellation: order=<orderId>`.
- 웹훅 응답: `LATE_DEPOSIT`(Toss 재시도 없음 — 200 ack).

**이때 실제 돈은 Toss에 들어와 있다.** 앱에는 환불 경로가 없으므로 운영자가 Toss에서 직접 환불한다:

1. [Toss 상점관리자](https://merchant.tosspayments.com) → 결제 조회에서 `orderId`(= Toss 주문번호)로 검색.
2. 해당 가상계좌 입금 건을 **전액 환불**(구매자 입금 계좌로 반환) 집행.
3. 구매자에게 안내(주문이 기한 만료로 취소되어 입금액을 환불했음).
4. 앱 상태는 `CANCELLED` 그대로 둔다 — 환불이 앱 밖에서 완결됐고, Toss 환불 웹훅(`CANCELED`)이
   와도 터미널 상태라 아무것도 움직이지 않는다(웹훅 응답 `IGNORED` — 정상. 감사 행도 중복되지
   않는다: LATE_DEPOSIT 감지는 입금 통보(권위적 `PAID`)에만 반응한다).

## 4. 하지 말 것
- 기한 전 `WAITING_FOR_DEPOSIT` 주문을 어떤 경로로든 취소하지 않는다(§2 이유).
- 뒤늦은 입금을 앱 상태 조작으로 "정산"하려 하지 않는다 — 환불만이 올바른 대응(§3).
- 승인 토큰을 공유/재게시하지 않는다(대상·10분 바인딩이지만 유효 기간 내 재사용 가능).
